# 项目内容归纳

更新日期：2026-07-22

## 1. 项目目标

使用 YOLO26 完成楔形片瑕疵检测，当前围绕三分类与单类 `defect` 检测开展实验，并为后续阈值选择、标注清洗和半监督学习做准备。

## 2. 本地内容清单

| 路径 | 内容 | 是否建议上传 GitHub |
|---|---|---|
| `photo/` | 原始三分类数据集、增强训练集及数据配置 | 否；图片和标签体积大，可能含敏感数据 |
| `photo_binary_defect/` | 三类合并为 `defect` 的数据集 | 仅上传可公开的配置或生成脚本 |
| `photo_binary_defect_clahe/` | 经过 CLAHE 的二分类数据集 | 仅上传可公开的配置或生成脚本 |
| `photo_tile_2x2/` | 2×2 切图数据集 | 仅上传可公开的配置或生成脚本 |
| `scripts/` | 数据增强、切图、格式转换、CLAHE、阈值评估脚本 | 是 |
| `stage1_yolo26m_baseline/` | 基线训练参数、曲线、可视化和权重 | 默认否；可挑选小型图表另行归档 |
| `outputs/` | 阶段性汇报 PPT 及检查文件 | 最终 PPT 可按需上传，检查文件不上传 |
| `work/` | PPT 构建过程、依赖和 QA 临时文件 | 否 |
| `*.zip` | 本地数据集压缩备份，总计约 7 GB | 否 |

## 3. 数据集关系

```text
photo（原始三分类）
├─ train_aug / train_aug_no_splash（离线增强）
├─ photo_tile_2x2（2×2 切图派生）
└─ photo_binary_defect（三类合并为 defect）
   └─ photo_binary_defect_clahe（CLAHE 派生）
```

所有派生数据均应能由原始数据和 `scripts/` 中的脚本重新生成。GitHub 主要保存“如何生成”和“得到什么结论”，而不是重复保存派生图片。

## 4. 已完成实验脉络

| 阶段 | 方向 | 关键结果 |
|---|---|---|
| Stage 1 | YOLO26 n/s/m 三尺度三分类基线 | YOLO26m 最好，`mAP50=0.617` |
| Stage 2 | 在线轻增强、延长训练、离线少数类增强 | 未超过基线，`scratch` 改善不明显 |
| Stage 3 | 2×2 非重叠切图 | `mAP50=0.578`，整体无收益 |
| Stage 4 | 单类 `defect` 与高分辨率 | 1536 输入最好，`mAP50=0.675` |
| Stage 4 | CLAHE + 单类 + 1536 | Recall 上升，但 Precision 和 mAP50 下降 |

完整参数、分类指标和结论见根目录的 `EXPERIMENT_RECORD_2026-07-01.md`。

## 6. 推荐记录原则

- 指标必须注明数据集划分：`train`、`val` 或 `test`。
- 区分“计划”“运行中”“已完成”“未复现”，不要把预期写成结果。
- 每个数字注明证据位置，例如 `results.csv`、终端输出或截图。
- 记录失败实验及原因，防止重复尝试。
- 不在 GitHub 提交原始数据、模型权重、密钥、绝对机器路径或临时依赖。
